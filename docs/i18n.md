# Internationalization (i18n)

Shekinah Live uses Flutter **gen-l10n** with ARB files generated from a Python catalog.

## Supported locales

| Code | Language   | ARB file        |
|------|------------|-----------------|
| `fr` | French     | `app_fr.arb`    |
| `en` | English    | `app_en.arb`    |
| `pt` | Portuguese | `app_pt.arb`    |
| `es` | Spanish    | `app_es.arb`    |
| `zh` | Chinese    | `app_zh.arb`    |

French (`fr`) is the **template locale** (`l10n.yaml` → `template-arb-file: app_fr.arb`).

Generated Dart lives under `lib/l10n/` (`app_localizations.dart` and per-locale implementations).

## Add a new localization key

1. **Edit the catalog** — Add a line in `tool/arb_catalog.py` inside `populate()`:
   ```python
   s("myNewKey", "Texte FR", "EN text", "Texto PT", "Texto ES", "中文")
   ```
   For placeholders or plurals, use `tool/generate_arb.py` (`add_special_strings()`, `PLACEHOLDER_META`) as examples.

2. **Regenerate ARB files** — From the project root:
   ```bash
   python tool/generate_arb.py
   ```

3. **Regenerate Dart** — Flutter picks up ARB changes via:
   ```bash
   flutter gen-l10n
   ```
   This also runs automatically on `flutter pub get` / build when `generate: true` is set in `pubspec.yaml`.

4. **Use in UI** — Reference `context.l10n.myNewKey` (see below).

## Add a new language

1. Add the locale code to `LOCALES` in `tool/generate_arb.py`.
2. Extend every `s(...)` call in `tool/arb_catalog.py` (and special strings in `generate_arb.py`) with a translation for the new language.
3. Run `python tool/generate_arb.py` then `flutter gen-l10n`.
4. Register the locale in the app:
   - `AppLocalizations.supportedLocales` is generated from ARB files; ensure the new `app_<locale>.arb` exists.
   - Add UI label for the language in settings (existing keys: `langFrench`, `langEnglish`, etc.) and wire locale selection if needed.
5. If the language needs date/number formatting, add an entry in `lib/core/l10n/locale_format.dart` (`ensureLocaleFormatInitialized`, `_intlLocale`).

## Using translations in UI

### `context.l10n`

Import `package:shekinah_live/core/l10n/l10n_extensions.dart` (or the project’s export). The extension on `BuildContext` provides:

```dart
Text(context.l10n.settingsTitle)
```

`AppLocalizations` is also available as `AppLocalizations.of(context)` where you do not have a `BuildContext` extension in scope.

### `entity_labels.dart`

`lib/core/l10n/entity_labels.dart` maps **domain/API values** (predication type, offline category, worship schedule, play/download subtitles) to localized strings. Pass `context.l10n` (or `AppLocalizations`):

```dart
predicationTypeLabel(context.l10n, predication.type)
offlineCategoryLabel(context.l10n, item.category)
```

Prefer this over duplicating switch logic in widgets.

### `locale_format.dart`

`lib/core/l10n/locale_format.dart` formats dates for the active `Locale`:

- Call `ensureLocaleFormatInitialized()` once at app startup (before formatting).
- Use `formatShortDate`, `formatLongDate`, or `formatCeremonyDate` with `Localizations.localeOf(context)`.

Do not hardcode `DateFormat` locale strings in presentation code; use these helpers so all five languages stay consistent.

## Configuration reference

| File | Role |
|------|------|
| `l10n.yaml` | gen-l10n paths and template ARB |
| `tool/arb_catalog.py` | Source of truth for most strings |
| `tool/generate_arb.py` | Writes `lib/l10n/app_*.arb` |
| `lib/core/l10n/l10n_extensions.dart` | `context.l10n` |
| `lib/core/l10n/entity_labels.dart` | Entity → label helpers |
| `lib/core/l10n/locale_format.dart` | Locale-aware dates |
